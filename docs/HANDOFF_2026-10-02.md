## 2. Tension you must know about: the PDF vs the repo's own docs

The repo's `DECISIONS.md` (2026-07) deliberately *deviated* from the spec PDF (no supervised injury prediction; the PDF's
35/20/20/15/10 weights "never adopted"; no MongoDB). The user now explicitly wants PDF behaviour. Resolution taken:

| PDF asks for | What was done |
|---|---|
| Weighted model 35/20/20/15/10 | **Adopted** (reverses the 07-11 decision). Weights are a *specification*, not fitted — documented as such. |
| 5 scores (injury risk, movement quality, biomech efficiency, fatigue risk, overall health) | All five returned in `sub_scores`, each with a `definition`. **Efficiency is an explicit PROXY.** |
| 6 injury categories | All six (`injury_categories`), as *levels* from named drivers. Video kinematics used only where evidence supports (ACL; trunk for back/shoulder). |
| Injury "probability prediction" | **NOT implemented.** No labelled injury dataset exists; a probability would be fabricated. Risk *levels* + drivers instead. User has not been asked to override this — if they want it, that is a conversation, not a code change. |
| MongoDB / TimescaleDB etc. | Untouched (still PostgreSQL only, per earlier decision). |

## 3. Root causes found (evidence, not guesses)

| # | Defect | How established |
|---|---|---|
| 1 | **A video was scored against itself.** `MIN_BASELINE_SAMPLES=10` counted per-frame *rows* (one clip ≈ 600+), and the baseline query included the scored video. | Reproduced: 1 video → HTTP 200; textbook squat 34.7 "moderate". Regression test: `test_a_lone_video_is_never_scored_against_itself`. |
| 2 | Per-frame baselines can't detect a shallow squat (its frame values also occur in a deep squat). | Reasoning + simulation; engine now uses video-level extremes. |
| 3 | In-distribution percentile ≈ 50 → every normal video looked "moderate". | Measured: fresh normal samples average ~51 (cross-fit) vs ~62 (in-sample). Tail-only scoring. |
| 4 | **`biomechanical_metrics.confidence` is VARCHAR(10); `'qualitative'` is 11 chars.** Migration 0002 widened the *wrong table*. Every frontal/"other"-view video (anything computing knee valgus) died at INSERT. | Reproduced by test; confirmed in `0001_init.py`. Fixed in model + migration 0003. |
| 5 | Pose pipeline discarded MediaPipe **visibility** → hallucinated limb coordinates stored as "validated" metrics. | Code read. Now stored raw + gated. |
| 6 | Timestamps from `cap.get(POS_MSEC)` (can be 0/duplicate on phone/VFR clips; Tasks `VIDEO` mode raises); no per-frame error isolation; portrait `VideoWriter` sized from `CAP_PROP_*`. | Code read; tests in `test_pipeline_loop.py`. |
| 7 | Hip flexion returned the raw interior angle (~180° standing). **Second layer found by tests:** it also used the same-side shoulder, leaking ~10° of lateral offset. | Unit test on synthetic pose (upright read 10.2°). |
| 8 | ACWR divided chronic load by *training days* (rest days ignored); RPE trend was `pass`; alerts broadcast to **every coach** and re-sent on every recompute; `anomaly_scores` never written; analytics trends looked up UUID vs str keys (`movement_type` always "unknown"); landing stamped `phase:"initial_contact"` on every frame. | Code read + tests. |
| 9 | Found only by fuzz/calibration: a clip shorter than the smoothing kernel crashed (`np.convolve mode="same"`); jitter counted hidden-leg garbage as noise (clip with one hidden leg graded `poor`); rep "duration" was ~12% under the true cycle. | Hypothesis counter-example; calibration run. |

## 5. Contract changes & deploy steps

* `GET /videos/{id}/risk-score` now returns `score_breakdown` keyed by the **five spec components** (each `{points,max,score,weight,effective_weight,available,detail}`), plus
  `sub_scores`, `injury_categories`, `data_completeness`, `missing_components`, `baseline{videos,required,excluded_incomplete}`, `quality`, `movement`, `reliability`, `engine_version`, `anomaly_features`.
  Old keys (`movement_anomaly`, `asymmetry_flag`, …) are gone. 202 payload now has `unit:"videos"`, `movement_type`, `excluded_incomplete`. New 409 (`VIDEO_NOT_READY`) and 422 (`NO_VALIDATED_METRICS`).
* Env: `MIN_BASELINE_VIDEOS` (default 10), `POSE_LANDMARKER_VARIANT` (lite|full|heavy; default **full**, was lite), `POSE_MODEL_COMPLEXITY` (legacy API, default 1), `POSE_LANDMARKER_MODEL_PATH`.
* New dependency (dev): `hypothesis==6.168.3`.
* **Deploy:** `alembic upgrade head` → `python scripts/reprocess_metrics.py --dry-run` → `python scripts/reprocess_metrics.py`.
  Reprocessing is **required** for old videos: hip-flexion semantics changed and old rows have no visibility.
* Expect on first read after upgrade: old scores are recomputed lazily (engine_version check); a recomputed video that is now high/critical **and was not high/critical under the old engine** will raise a one-time alert.
* Users will see **202 "baseline building"** until ≥10 other completed videos of that movement exist. That is intended (the old behaviour was the bug).

## 7. NOT verified — do not assume

1. **Nothing was run on a real video.** Sandbox could not download YOLO/MediaPipe weights. All video-analysis verification is synthetic motion with *known* ground truth plus injected noise/dropouts/occlusion/spikes/camera roll. Real-footage behaviour (smoothing cut-offs, visibility threshold 0.5, quality thresholds, CLAHE+gamma benefit) is **unmeasured**.
2. The `pose_landmarker_full` download URL/path and the offline fallback were unit-tested only with a mocked `urlretrieve`.
3. **Blended anomaly false-positive rate after the (1+4/n) widening was not re-measured** (z-component alone: 16%→4% at n=10; blended was 14% at n=10, 8% at n=30 *before* widening).
4. The new results page was never opened in a browser. `docker compose up` was never run (native services only).
5. Reprocess script and migration were exercised on synthetic data / an empty database, not on the user's real database.
6. `trunk_rotation` is tagged `validated` in `throwing.py` with no support in SCIENCE_CONSTRAINTS (only sagittal hip/knee/trunk-lean are evidenced). Left unchanged — worth a decision.

## 8. Heuristic parameters (named constants; NOT clinically validated)

`scoring.py`: LSI ramp 90→70; history levels 100/70/40/(40/25/10) + 24-month recency; ACWR 1.3/1.5/2.0 mapping (zones from Gabbett 2016); RPE-trend ramp 0.5→2.5; drift ramp 5%→30%; CV ramp 5%→25%.
`anomaly.py`: tail floor 90th pct, flag 95th, z-tail 3→5 widened by (1+4/n), feature flag |z|≥2, z-scale floor = RMSE/2.
`analysis.py`: visibility 0.5, max gap 0.3 s, Hampel 3σ/1 cm, per-movement cut-offs (squat 4 Hz … sprint 12 Hz), grade thresholds (usable 50/80%, jitter 3.5/6.5°, interpolated 15%, tilt 10°, clip ≥1.5 s).
`movement_analysis.py`: noise anchor 6.5° RMSE (SCIENCE_CONSTRAINTS) → min range ≈20°; gait band 15%, ankle-separation floor 0.15 m, cadence 60–330 spm, ≥4 steps; mislabel needs ≥6 steps.
`injury_categories.py`: kinematic z ramp 1→3, driver weights, valgus flag 10%.

## 9. Known limitations (honest)

* Camera tilt is **reported, not corrected** (correcting without real clips risks erasing true forward lean).
* Left/right comparisons from a single side-on camera are fragile (far leg occluded) — guarded by a 60% leg-visibility rule, but still a monocular limitation.
* Mirrored/selfie clips swap L/R labels; no rotation probe (sideways frames if the OpenCV backend doesn't auto-rotate); `sport_specific` pools unrelated drills into one baseline.
* Baselines are population-level only (per-athlete baselines deferred). Cached scores don't refresh as the baseline grows (`?recompute=true`).
* Rep "active time" excludes flat valley edges; use `mean_cycle_s` for true cycle time.
* Step-time asymmetry degrades under extreme landmark noise (16% apparent at 12 cm noise; <5% at realistic 3 cm).
* `report_exports` model has no migration (pre-existing; unused by live code).

## 11. Working notes

* Tests: `cd backend && pytest -q` (needs Postgres/Redis as in `tests/conftest.py`). Full run ≈ 2.5 min on one CPU. `tests/synth.py` is the ground-truth motion generator (squat/run + noise, spikes, dropouts, occlusion, camera roll) — extend it before adding analysis features.
* Mutation harness: `python scripts/mutation/run.py scripts/mutation/mutants.py` (see its docstring). If you change a constant a mutant targets it reports `BAD_MUTANT` — update the catalogue. A survivor means a test gap *or* an equivalent mutant: decide, don't dismiss.
* Sandbox gotcha (if you are in a similar one): background daemons (Postgres/Redis) may be reaped between tool calls — start them in the same command as the test run; run long jobs detached with `setsid nohup`.
